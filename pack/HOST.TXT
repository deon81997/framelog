FRAMELOG host tools - the PC at the other end of the serial cable
==================================================================

What you need
  Python 3 (https://www.python.org/, tick "Add to PATH" on Windows) and a
  serial port (USB adapter is fine) with a null-modem cable to the game PC.
  FLLOG.BAT installs pyserial + matplotlib the first time it runs. By hand:
    py -m pip install pyserial matplotlib

Windows, the easy way
  1. Double-click FLLOG.BAT. It lists the serial ports, asks for the port
     and a name for the run, then logs. Start the game on the game PC
     (FRAMELOG must be loaded there), press Ctrl+C here when it is done.
     The run is saved as NAME.csv in this folder, with its stats.
  2. Repeat for every game / card / CPU you want to compare.
  3. Double-click REPORT.BAT: it builds report\index.html from all the
     CSVs here (the Retro GPU Shootout: a page per game, per card and per
     run, CSV/JSON export, 3D charts if you say y) and opens it.

Video-card test, the easy way (test13; no typing on either PC)
  Host: double-click CARDS.BAT, give the port and the PC's name once, pick
  the part. Retro PC, MS-DOS mode: CD \FRAMELOG, then CARDS1 (part 1),
  reboot + CARDS2 (part 2), and CARDS3 only if CARDS2 asks for it. Windows
  98: pick part 4 here, then double-click WIN98\CARDS98.BAT. Press a key
  on the retro PC when this window says "waiting for step"; in Duke press
  Esc, Q, Y after about a minute. CSVs land in results\<PC name>\, the
  retro PC's files in C:\FLRES. Send both folders.

Command line (Windows: py, Linux/Mac: python3 and /dev/ttyUSB0)
  py fllog.py COM3 -o run.csv --label NAME [--gpu G --res 640x480 --game Q2]
  py fllog.py COM3 --suite suite.ini -o results\ --report report\
  py flstats.py a.csv b.csv --png compare.png
  py flreport.py results\ -o report\ [--3d]
  py flcap.py capture.avi -o run.csv --fps 70.086   (needs opencv-python numpy)
  LOG.BAT COM3 run.csv NAME       (old short form of FLLOG.BAT)

No bytes ("NO BYTES AT ALL" from FLLOG, or frames=0 junk=0)
  Not one byte reached this PC, so the link is dead - not the game. Check,
  in this order (stop at the first one that fixes it):
  1. Port here: FLLOG says "PORT BUSY" when another program has it (DBGLOG,
     PuTTY, a second FLLOG) - close it. Device Manager > Ports shows the
     USB adapter's COM number and no yellow mark (driver installed).
  2. Cable: NULL-MODEM (crossed TX/RX). A straight 9-pin cable sends
     nothing across; a null-modem adapter on it fixes that.
  3. Game PC: its COM port is enabled in the BIOS (COM1 = 3F8, IRQ 4). Dell
     D810: the serial port is on the dock - dock it BEFORE power-on (no COM
     port after a hot dock) and set its serial port to COM1 in BIOS (F2).
     FRAMELOG says "no UART at 3F8" when the port is not there.
  4. Two-minute test without FRAMELOG: double-click LINKTEST.BAT here
     (listens at 9600), then on the game PC in plain DOS:
         MODE COM1:9600,N,8,1
         ECHO HELLO > COM1
     HELLO here = cable and ports work: go back to FLLOG (115200, FRAMELOG
     /COM:1). Nothing = cable, BIOS or dock; try COM2 (MODE COM2:...) in
     case the dock's port is COM2, then FRAMELOG /COM:2.
  5. Link works but still no frames: run FRAMELOG /STATUS on the game PC
     after a try - "host bytes" 0 = this PC's S bytes never arrive (start
     with FRAMELOG /AUTO instead); "bytes sent" 0 = no game frame was seen.
  "bytes came but no FRAMELOG frame" = baud differs: same number at both
  ends (FRAMELOG /COM:1,115200 and fllog --baud 115200, the default).
